## Answer

Ticket 07's share of C2 is built, reviewed and on `main`, and C2 stays In progress. In `internal/core/workspace`, a writer is a typed handle that binds a context to a task's scratch. The task's own context writes its dedicated scratch; another context of the same agent gets a temporary scratch forked from the task's latest committed tip, never from `main` or the task's uncommitted files. Core commits each observation of a scratch on its private branch and records the paths it changed and the context that wrote them, in F2-07's records as the owner froze them (D119). A temporary's work returns by merge-back: a fast-forward when the task has not moved since the fork, otherwise Git's merge with the fork as the explicit base. A conflict changes neither scratch and stays work, and each outcome is a durable notice the task's context reads. A merge-back waits for the task's turn and for a capture's protected window, not for a live request. An admission records the observation and the merge-backs it carries. C2's product still admits nothing until C4, and C3 authenticates callers and delivers notices into turns; canonical acceptance (ticket 08) and policy activation (09) remain. [B26](../../../docs/DECISIONS.md#b26-c2-temporary-scratches-private-observations-and-merge-back-ticket-07) records the build, including its amendments of ticket 05's writer call and closure; Core Appendix A.13 records the costs of observations, temporaries, leases and merge-backs. All of this is verified on Windows; the Linux and macOS rows first run in C3's CI.
