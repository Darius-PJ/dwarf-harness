## Answer

Ticket 05's share of C2 is built, reviewed and on `main`, and C2 stays In progress. Core's package `internal/core/workspace` registers a Git workspace when the owner approves its capture inputs: its Git version and object format, seven Git settings such as `core.autocrlf`, and his local and global ignore and attribute files, which Core pins as bodies and only he can update. `main` is never checked out. Each bound context gets one private scratch per workspace, a linked worktree on its own branch cut from `main`, and no scratch's name is reused. A capture is reserved first and answers busy at once, with no snapshot, wait, retry or interrupted writer, when its scratch or the capture-byte budget is taken. It reads every eligible file, has Git build the tree under the pinned inputs and checks that tree against the bytes it read; it refuses unsupported file kinds, filters and conversions, path collisions, lossy normalization and exhausted caps, and a sealed tree cannot change afterwards. Closing a scratch first observes it and refuses while any edit is unrepresented; the removal never follows a junction or symlink and is retried until it completes. A promotion request answers unavailable, because C2 has no validator, and records nothing. The service writes the four F2-05 records the owner froze (D115), checks their rules when it appends and when it opens a log, and, each time it opens, removes what a crash left behind, keeping any branch whose base it cannot prove. [B23](../../../docs/DECISIONS.md#b23-c2-the-git-program-private-scratches-and-exact-capture-ticket-05) records the Git, scratch and capture mechanics and [B24](../../../docs/DECISIONS.md#b24-c2-the-workspace-service-and-its-records-ticket-05-s3) the service and its records, both from the design the owner approved as ruled at OG-A; Core Appendix A.11 records the capture costs. All of this is verified on Windows; the Linux and macOS rows first run in C3's CI. Tickets 06–09 add the four-checkpoint queue, request deduplication and the merge train, temporary scratches, finalization and recovery, and policy activation; accepted promotion waits for C4.
