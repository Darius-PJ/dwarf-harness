## Acceptance criteria

- [ ] Both optional stages start disabled and ordinary routing still works with them off. A local embedding implementation must pass its bounded resident-memory and replay value gate; a paid stage must exceed its full expected-benefit threshold including reservation, tokens, latency and device cost.
- [ ] At most one paid classification runs per new user/message turn after cheaper stages; tool continuations and escalations never reclassify. Send only current input plus at most three prior same-context user inputs within 8,000 characters; unsupported attachments are omitted/refused rather than smuggled into an unbounded profile.
- [ ] Use the context's active provider unless a current explicit grant names this exact other provider and context. Missing/expired/mismatched grants deny the send and retain the local heuristic; another context's provider selection confers nothing.
- [ ] Every remote classifier request uses the same Core sealed finite-bound admission and settlement, separately from the eventual main-model request. Its unknown hold survives timeout; fallback never releases it or triggers a second classifier call.
- [ ] Validate structured Needs output; abstention, timeout or invalid output uses only the same context's authorized local fallback. Binding/authorization failure stops rather than falling through to another context or provider.
- [ ] Consented replay demonstrates each enabled module's net value with success, misrouting, full cost, latency and whole-process resource results. A non-beneficial module remains off; provider-hosted search/iterations/media stay refused absent their own separately verified finite profile and gate.
