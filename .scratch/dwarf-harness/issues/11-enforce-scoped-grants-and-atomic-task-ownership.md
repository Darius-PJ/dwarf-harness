## Acceptance criteria

- [x] Default-deny actor/context/operation/target checks apply at admission, dispatch and disclosure; owner ceilings only attenuate via explicitly authorized task/context grants.
- [x] In-scope local tools require no paid consent; shell/process/network/connector/model effects need separate current grants.
- [x] Atomic expected-version task claims/assignments/transitions refuse races and stale reassignment; revocation is checked before new effects and reads.
- [x] Bound non-paid StartTurn admission and artifact/current-context access work before provider integration; permission denial and resource exhaustion stay distinct.
- [x] Core alone owns durable non-paid capacity admission; paid provider work extends the same BudgetBook rather than creating a second wallet or inferred allowance.
- [x] Task state, claims, assignments, grants and pending work change only through producer-owned typed Core transitions that bind actor, context, operation and target, check expected version and current authority, publish required private bytes and a bounded replay-complete event group through the existing sequencer, then update rebuildable authorized projections before acknowledging. Model, Git and check effects stay outside the short transition and return through typed, identity-bound results; an intent or command receipt is never proof that the external effect happened.

## Answer

Ticket 11 is built, reviewed and on `main`. Core's private-state service, `internal/core/agents`, now enforces scoped authority. The owner issues root grants, and a grant may delegate attenuated children, each bounded by its resource kinds, operations, targets, units and depth; one leaf and its complete current chain authorize a whole operation, checked at entry, after preparation, before commit and before disclosure, and a revocation is irreversible. `BindAgent` binds one agent's origin for a trusted host, not an authentication, and the agent reaches only what its grants name. Tasks are immutable definitions whose claims, assignments, reassignments and transitions each check the expected version, assignment and generation under the lock; a reassignment gives the task a new assignment and a fresh work context, and fences the old context. Core's one budget book holds the owner's finite non-paid limits, consumed units and holds, and checks authority before capacity, so a denial stays distinct from busy. `StartTurn` and local-work admission are admitted or busy at once and execute nothing; dispatch and endings enter only through host-only methods, which have no production caller until ticket 15. The agent's private writes and private and artifact reads verify their bytes. Each transition commits one ledger group ending in its receipt before the acknowledgement. At restart, Open rebuilds everything from the ledger, appends nothing and lists interrupted work, which the host ends explicitly. The service writes F3-11 as the project manager froze it (D140). [B32](../../../docs/DECISIONS.md#b32-c3-scoped-grants-and-atomic-task-ownership-ticket-11) records the design as ruled, the project manager's answers that changed reviewed behaviour, the reviews and the service's limits. The rows ran on one Windows machine. CI run 13, on 6e11d49, passed S1 and S2 on Windows, Linux and macOS; S3a, S3b and S4 first reach CI with this ticket's push after its close (D141).
